EC2 vs FleetWatch: Architecture Deep-Dive

This reference details the architectural parity between Amazon Web Services (AWS) production infrastructure and the FleetWatch educational simulation engine.

1. EC2 Instance Lifecycle & Provisioning

Compute

Real AWS EC2

Instances transition through pending (hypervisor allocating hardware & booting guest OS, 30s-120s), running, stopping, stopped, shutting-down, and terminated.

FleetWatch Simulator

Simulates boot time (~3s scaled to tick speed). Instances transition faithfully across all 6 lifecycle states with realistic status checks and hourly cost accrual per tick.

2. Multi-AZ High Availability

Resilience

Real AWS EC2

Spreads instances across physically isolated data centers with independent power, cooling, and networking within a region (e.g., ap-south-1a/b/c).

FleetWatch Simulator

Maintains 3 distinct AZ racks. The ASG uses round-robin capacity balancing to ensure equal distribution across all non-impaired AZs.

3. Auto Scaling Group (ASG) Min / Desired / Max

Elasticity

Real AWS EC2

Maintains instance capacity bounds. Automatically terminates unhealthy instances and launches replacements to maintain desired count while respecting min/max constraints.

FleetWatch Simulator

Every tick monitors healthy instances. If an instance crashes or stops, the ASG launches a replacement in the least-populated AZ to preserve desired capacity.

4. Target Tracking vs Step Scaling Policies

Auto Scaling

Real AWS EC2

Target Tracking: calculates capacity proportional to metric gap (FleetCPU / TargetCPU * CurrentSize). Step Scaling: executes discrete step adjustments based on CloudWatch alarm breach magnitude.

FleetWatch Simulator

Implements proportional Target Tracking formulas and discrete multi-tier Step Scaling rules with live cooldown enforcement.

5. Application Load Balancer (ALB) & 503 Spillovers

Networking

Real AWS EC2

Evaluates target health checks. Distributes HTTP traffic exclusively across healthy targets. If total capacity is saturated, responses return HTTP 503 Service Unavailable.

FleetWatch Simulator

Distributes incoming RPS across running targets only. Excess traffic beyond aggregate capacity triggers dropped request counters and visual red particles.

6. CloudWatch Telemetry & Alarm States

Observability

Real AWS EC2

Collects 1-minute CPU metrics per instance and average fleet utilization. Triggers CloudWatch Alarms when metrics breach thresholds for consecutive periods.

FleetWatch Simulator

Renders a live 60-second telemetry canvas showing real-time instance loads, fleet average, alarm thresholds, and instantaneous alarm triggers.

⚠️ Architectural Constraints & Non-Simulated Features

Out of Scope
  • VPC & Subnet Networking: No packet-level CIDR routing, NAT Gateways, Internet Gateways, or ENI IP allocation.
  • Storage Volumes: No EBS IOPS bursting, gp3 throughput throttling, or snapshot restoration latencies.
  • Security Groups & NACLs: No stateful firewall packet filtering or IAM instance profile authorization checks.
  • Warm Pools & Predictive Scaling: Warm pool pre-initialized states and Machine Learning-based predictive scaling algorithms are omitted.
  • Billing Granularity: Real AWS bills per second with a 60-second minimum; FleetWatch calculates exact fractional cost per 500ms simulation tick.
